# @onwave/api-contract

OpenAPI-схема — источник правды (ONW-8).

- Бэкенд реализует схему, мобилка генерирует из неё Dart-клиент (ONW-42).
- Правки начинаются здесь, а не в коде.
- CI валидирует схему и проверяет, что сгенерированный клиент не разъехался с ней.

## Команды

```bash
pnpm contract:lint     # spectral, гоняется в CI
pnpm contract:mock     # мок-сервер на :4010 из примеров схемы
```

## Мок-сервер

Мобилка поднимает ленту, не дожидаясь бэкенда: `prism` отдаёт ответы,
сгенерированные из схемы, и валидирует запросы по ней же. Если клиент шлёт
что-то не по контракту — это видно сразу, а не на интеграции.

```bash
pnpm contract:mock
curl 'http://localhost:4010/events?city=tbilisi'
```

Базовый URL в dev-флейворе мобилки переключается на `http://localhost:4010`.

## Что зафиксировано в схеме

| Решение | Где смотреть |
| --- | --- |
| Один формат ошибки с машиночитаемым `code` | `components.schemas.Error` |
| Курсорная пагинация, не offset | `components.parameters.Cursor` |
| Время в UTC, локальное считается по `City.timezone` | `City`, `EventSession` |
| Гостю доступно всё чтение | операции с `security: []` |
| Оплаты внутри нет, только внешний `ticketUrl` | `EventDetail.ticketUrl` |
| Жалобы и блокировки (App Store Guideline 1.2) | тег `safety` |

## Правки схемы

1. Меняем `openapi.yaml`.
2. `pnpm contract:lint` — должно быть чисто.
3. Перегенерировать Dart-клиент (ONW-42) и закоммитить вместе со схемой.

Шаг 3 обязателен: CI падает, если клиент отстал от схемы.
